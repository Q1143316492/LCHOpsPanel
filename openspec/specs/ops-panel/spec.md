# Spec: Operations Panel

## Summary

The core feature of LCHOpsPanel. Displays a categorized tree of workspace shortcuts — files to open, scripts to execute, and arbitrary shell commands. Users can add, edit, and delete items via QuickInput dialogs.

## Tree Structure

```
Operations Panel
├── 📁 Category A (N items)
│   ├── 📄 file-item        → left-click opens in editor
│   ├── 📝 script-item      → right-click menu: Execute / Open in Terminal
│   └── 🖥  command-item    → right-click menu: Execute Command
└── 📁 Category B (M items)
    └── ...
```

- Categories are shown only if they contain at least one item.
- Items not assigned to any known category appear under a synthetic "Uncategorized" node.
- Category nodes are always expanded by default (`Expanded` collapsible state).

## Item Types

| Type | Icon | Left-click | Context menu |
|---|---|---|---|
| `file` | `file` | Open in editor | Edit, Delete |
| `script` | `file-code` | (none) | Execute Script, Open in Terminal, Edit, Delete |
| `command` | `terminal` | (none) | Execute Command, Edit, Delete |
| `category` | `folder` | Toggle expand | (none) |

## Behaviors

### Add Item (`lchOpsPanel.addItem`)
1. QuickPick: select type (File / Script / Command)
2. InputBox: name
3. InputBox: path (file/script) **or** command string (command type)
4. InputBox: description (optional)
5. QuickPick: category (existing list + "New Category" option)
6. Item appended to `config.items`, saved to disk.

New categories entered here are appended to `config.categories`.

### Edit Item (`lchOpsPanel.editItem`)
- Re-prompts name, path/command, description.
- Does NOT re-prompt category (category change not supported in edit flow).
- Updates the matching item by `id`, saves to disk.

### Delete Item (`lchOpsPanel.deleteItem`)
- Shows modal confirmation dialog before deleting.
- Removes item by `id` from `config.items`, saves to disk.

### Execute Script (`lchOpsPanel.executeScript`)
- Resolves absolute path; checks file exists.
- Creates a new terminal, `cd`s to the script's directory, runs via `buildRunCommand`.
- Extension mapping: `.py`→`python`, `.js`→`node`, `.ps1`→`powershell -ExecutionPolicy Bypass -File`, `.bat/.cmd`→direct call, `.sh`→`bash`, others→direct call.

### Open in Terminal (`lchOpsPanel.openInTerminal`)
- Creates a terminal with CWD set to the item's parent directory.
- Does not run any command.

### Execute Command (`lchOpsPanel.executeCommand`)
- Creates a terminal, `cd`s to workspace root, sends the `command` string.

### Open File (`lchOpsPanel.openFile`)
- Opens the item's path in a VS Code text editor tab.
- Shared with the Notices feature for `notice-file` items.

### Open Config File (`lchOpsPanel.openConfigFile`)
- Opens `.lch-ops-panel.json` in a text editor tab.

### Refresh (`lchOpsPanel.refresh`)
- Forces a disk reload via `store.reload()`, then fires tree change event.

## Data Model

```typescript
interface OpsItem {
  id: string;          // random alphanumeric, generated on creation
  name: string;
  type: 'file' | 'script' | 'command' | 'category';
  path?: string;       // required for file/script; absent for command
  command?: string;    // required for command type
  description?: string;
  category?: string;   // display category name; absent = Uncategorized
}
```

## Invariants

- `id` is never reused; generated by `generateId()` (Math.random base-36).
- `type: 'category'` items are synthetic — they exist only in the tree render layer, never persisted.
- All mutations go through `OpsTreeProvider` methods (`addItem`, `deleteItem`, `updateItem`) which call `store.save()`.

## Non-goals

- Drag-and-drop reordering of items or categories.
- Nested categories (only one level of category hierarchy).
- Bulk import/export of items (see Notices for file-collection management).
